How a question moves

Three hand-offs between a question and a checked answer.

One rule runs through all of it: nothing is cut, annotated or pulled unless our own code found a verbatim quote supporting it in the source text. The model proposes. Our code checks.

  1. 01

    Find what replaced what

    A model reads the pages and proposes which claim superseded which. Every quote it cites is searched for, word for word, in the stored page. Quotes that don’t verify are thrown away.

  2. 02

    Put the winner in front of the model

    Spans are cut, not documents: a page that says “previously X, now Y” survives. When two pages disagree and nothing orders them, the answer is CONTESTED. Currant never guesses a winner.

  3. 03

    Return a receipt anyone can replay

    The receipt hashes the exact text the model saw. Replaying recomputes that hash, with no key and no network, and it matches or it fails.

Built on

SERV Reasoning, by OpenServ does every model call: proposing claims, proposing which replaced which, and answering, with one model, gpt-6-luna.

Reppo gave independent verdicts: its judges scored our answers against a baseline in 21 public evaluations.

What we measured

    
The numbers, including where we lost.

    
The held-out figures come from 93 synthetic test items, scored once after a public freeze. The audit is Reppo’s own judges scoring our answers on real conflicts.

    

      
0.857precision on 28 cuts, held out (dev was 1.000)

      
0.828recall, 24 of 29 held out (dev was 0.892)

      
84.2%answers right with Currant when only the stale page was retrieved, against 0% without

Why we lost points

        
    
          
  • When two pages disagree and nothing orders them, our answer says only that the documentation is contested. It does not quote either value.
    • 
          
  • The judges marked that incomplete and preferred a confident “440” that matched the live charge.
    • 
          
  • The fix is clear: a contested answer should quote both values. It changes code, so it would break the link to the frozen results, and it has not been made.
    • 
        

      

      

        
What this does not show

        
    
          
  • It does not show a lift on real documentation. The lift is measured only on synthetic items, with one model.
    • 
          
  • It does not show recall on real docs: the detector missed one of three conflicts, and we have no labels.
    • 
          
  • On a second vendor’s public docs (59 pages, 463 claims verified of 611 proposed) it ran with no code change and found nothing to report. That shows it runs elsewhere, not that it works there.
